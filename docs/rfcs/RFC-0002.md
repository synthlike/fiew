# Use an explicit current-review pointer for routine agent handoff

## Summary

Remove routine review-ID exchange by giving each repository one explicitly selected current review while retaining opaque review IDs for storage, history, and explicit access.

## Motivation

The current reviewer-agent loop requires the reviewer to copy a generated review ID to the agent. A deterministic ID derived from staged content appears to avoid that exchange, but review conversations evolve while staged, unstaged, and untracked changes change. Content-derived identity would therefore disconnect replies from an existing conversation or conflate snapshot identity with conversation identity.

The repository already scopes local review discovery. One explicit current-review pointer gives reviewer and agent commands a stable shared default without weakening durable review identity.

## Requirements and constraints

- Routine reviewer-agent commands require no exchanged review ID.
- Internal review IDs remain opaque, stable, and available for history and explicit access.
- Each repository has at most one current review.
- `review start` creates a review and atomically marks it current.
- `review open <review-id>` atomically makes that review current; `review open` opens the existing current review.
- `review show` defaults to current while retaining `review show <review-id>`.
- `review reply <thread-id> --body-file <path>` defaults to current while retaining the explicit `<review-id> <thread-id>` form.
- Approval does not clear current; it changes only through `review start` or explicit `review open <review-id>`.
- Missing, malformed, or dangling current state fails explicitly. Commands never guess from timestamps, filenames, or directory order.
- Current selection remains reviewer-controlled. Agent `show` and `reply` operations do not change it.
- Existing role authority, atomicity, schema refusal, and approval-sensitive exit behavior remain unchanged.

## Non-goals

- Deriving conversation identity from staged files or any Git snapshot.
- Removing durable review IDs or historical review access.
- Multiple simultaneous current reviews in one repository.
- Automatic current selection from the newest review.
- Clearing current automatically after approval.

## Open questions

None.

## Options

### Option A: Deterministic content-derived review IDs

Hash a canonical representation of staged or working-tree changes so fiew and an agent independently calculate the same ID. This avoids a pointer, but the ID changes as work evolves, excludes or complicates non-staged state, and makes immutable snapshot identity incorrectly serve as mutable conversation identity.

### Option B: Discover or guess the newest review

Default commands to the lexicographically or temporally newest review. This avoids another state file but becomes ambiguous after historical files are copied, clocks differ, or a prior review is explicitly resumed. Failures can silently target the wrong conversation.

### Option C: Explicit repository-local current pointer

Persist one small, atomically replaced current-review reference under `.reviews/`. Commands use it only when an ID is omitted. Explicit reviewer start/open operations update it; agent operations never do. Missing or invalid references fail rather than guess.

## Recommendation

Choose Option C. It cleanly separates stable conversation identity from changing reviewed content and removes routine ID exchange without sacrificing explicit historical access.

## Resolution

Accepted by the decision owner. Use Option C exactly as recommended: one explicit repository-local current-review pointer, changed only by reviewer `start` or `open`, with ID-optional routine commands and explicit failure rather than inference.
