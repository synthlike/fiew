# Use unified internal JSON artifacts for reviews and bookmarks

## Summary

Decide whether repository-local reviews and bookmarks should use a common schema-versioned JSON envelope as fiew's private canonical representation, with command output treated as a projection rather than the stored document.

## Motivation

Reviews currently use the public `fiew.review/v1` Markdown format because external agents were originally expected to retrieve files directly. Agents now use only `fiew review show` and `fiew review reply`, and the reviewer does not require direct file readability. Markdown therefore imposes structural parsing and arbitrary-body escaping complexity without serving an established access requirement.

Bookmarks currently use a JSON envelope named `fiew.bookmarks` plus a separate numeric version. The desired naming is consistent singular, embedded-version schema identifiers: `fiew.review/v1` and `fiew.bookmark/v1`.

This revisits the storage-format portion of ARP-0007 while retaining reviewer authority and command-mediated agent access.

## Requirements and constraints

- Reviews remain repository-local under `.reviews/`.
- Bookmarks become repository-local under `.bookmarks/`.
- Both artifacts use schema identifiers of the form `fiew.<artifact>/v<version>`.
- Stored files are private implementation details and need not be comfortably human-readable.
- `fiew review show` remains the supported way to render review data as JSON or Markdown.
- Agent-facing output need not reproduce private internal metadata, but must preserve the complete public review semantics required to read and reply safely.
- Atomic replacement, validated backup recovery, and future-schema refusal remain required.
- Agents do not gain direct review-file mutation authority.
- fiew does not inspect or modify Git ignore configuration.

## Non-goals

- A manually editable storage format.
- Supporting direct agent access to stored review or bookmark files.
- A hybrid JSON/Markdown source-of-truth.
- Migrating unreleased development bookmark data.

## Open questions

None.

## Options

### Option A: Keep canonical review Markdown and bookmark JSON

Preserves direct review inspectability and ARP-0007's existing format. It retains two serialization disciplines and the complexity of distinguishing arbitrary Markdown bodies from review structure. Direct readability is no longer an established requirement.

### Option B: Use canonical JSON for both artifacts

Store each artifact in a schema-versioned JSON envelope while exposing stable JSON and Markdown projections through fiew commands. This provides strict typed parsing, straightforward arbitrary Markdown comment bodies, consistent recovery behavior, and freedom to evolve private metadata separately from public output. Stored files are less pleasant to inspect directly.

### Option C: Split metadata and bodies across JSON and Markdown

Keeps comment bodies readable while structuring metadata, but introduces multi-file atomicity, cross-file identity, and recovery complexity without an established requirement.

## Recommendation

Choose Option B. Use `fiew.review/v1` and `fiew.bookmark/v1` as canonical schema identifiers. Treat stored JSON as private and command output as an explicit public projection. Do not promise round-tripping between `review show` output and stored files.

## Resolution

Accepted by the decision owner.

Use Option B with a common `{ "schema": "fiew.<artifact>/v<version>", "data": ... }` envelope and no separate numeric version. Canonical files are `.reviews/<review-id>.json` and `.bookmarks/bookmarks.json`, with same-directory `.bak` validated backups. Existing Markdown reviews and global bookmark data are not migrated and must be rejected or ignored as legacy rather than interpreted as current state.

`fiew review show` remains the only supported agent read surface. Its JSON and Markdown forms are public projections: both preserve complete public review semantics, while storage-only repository identity, recovery, allocation, and re-anchoring metadata may be omitted. fiew neither checks nor modifies Git ignore configuration.
