# Keep Mermaid rendering outside fiew

## Context

fiew previously planned an optional terminal-text Mermaid preview in [Render a Mermaid subset as terminal text](<docs/decisions/ARP-0004.md>). Further product review found that diagram rendering does not fit fiew's source-first design or its premise as a focused code, diff, and codebase navigation tool. Retaining the feature would add a specialized parser and subprocess integration that does not strengthen the core viewing workflow.

## Decision

Do not add Mermaid-specific recognition, rendering, preview commands, runtime dependencies, or verification requirements to fiew. Mermaid fences remain visible as ordinary Markdown source and receive only the generic Markdown behavior defined by [fiew v0.2](<docs/specs/fiew-v0-2.md>).

Remove Mermaid preview from the v0.2 scope rather than deferring it to a later release.

## Rationale

Showing source directly is consistent with fiew's read-first premise and keeps attention on code, diffs, and repository navigation. A partial Mermaid renderer would add product surface, failure states, subprocess lifecycle work, and compatibility claims while supporting only a subset of diagrams. Generic Markdown fence handling preserves access to the content without making fiew a diagram renderer.

## Consequences

- The optional `mermaid-ascii` runtime dependency is removed from planned scope.
- No Mermaid-specific command, adapter, cache, diagnostic category, fallback state, test matrix, or smoke-test requirement should be introduced.
- Existing Mermaid research and resolved planning records remain historical evidence and do not define current product scope.
- [Render a Mermaid subset as terminal text](<docs/decisions/ARP-0004.md>) is superseded. Mermaid-specific clauses in the broader application architecture decision no longer apply.
