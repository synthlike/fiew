# Use trusted ZLS as an optional definition provider

## Context

fiew v0.1 must navigate from a Zig selection to its semantic definition while remaining useful when no language server is available. It must preserve the read-only source and Git boundary. ZLS can inspect project build information and may execute repository-controlled Zig build logic, so launching it is a trust decision. Evidence is recorded in [ZLS definition-navigation constraints for fiew v0.1](<docs/research/zls-definition-navigation-constraints-for-fiew-v0-1.md>), and observable behavior is owned by [Define the initial LSP navigation contract](<.project/issues/ISSUE-0010-define-the-initial-lsp-navigation-contract.md>).

## Decision

Use a user-installed ZLS 0.16.x executable from `PATH` as the only v0.1 language server and only for Zig `textDocument/definition`. Run at most one lazy ZLS process per open repository. Require explicit persisted trust for the canonical repository identity before launch and provide trust revocation that stops the process.

Advertise only implemented LSP capabilities. Support UTF-8 and UTF-16 positions, balanced document open/close notifications, request cancellation, and orderly initialize/shutdown. Enforce fiew's read-only boundary by refusing workspace edits and rejecting command execution, file operations, formatting, rename, and other unsupported requests.

Tie every definition request and result to immutable repository, document-version, selection, and request-generation identities. Accept only validated `file:` locations. Treat ZLS as optional: unavailable, untrusted, incompatible, slow, crashed, stale, or invalid behavior leaves normal text and Tree-sitter navigation intact.

## Rationale

ZLS is the focused semantic provider for the selected Zig toolchain. A definition-only capability set delivers the required navigation workflow without introducing general IDE behavior. Explicit trust makes potential repository-code execution visible. Snapshot validation and bounded requests prevent asynchronous responses from navigating the user away from current content. A complete non-LSP fallback preserves the core read-first workflow.

## Consequences

- Users install and update ZLS independently. fiew requires the 0.16 minor line and does not bundle or download it.
- ZLS startup and requests run only after repository trust. Disabling build-on-save reduces behavior but is not represented as a sandbox.
- fiew must implement JSON-RPC framing, lifecycle state, position conversion, cancellation, result validation, and process cleanup.
- The two-second definition timeout and tested ZLS patch version remain explicit compatibility facts, not broad performance guarantees.
- Markdown LSP, diagnostics, hover, references, symbols, completion, rename, formatting, code actions, commands, and generic server configuration are deferred.
