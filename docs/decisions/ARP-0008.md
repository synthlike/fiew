# Store reviews and bookmarks as private repository-local JSON artifacts

## Context

The repository-local Markdown review format was selected when external agents were expected to discover and parse review files directly. The command-mediated interface now makes `fiew review show` and `fiew review reply` the supported agent boundary, and the reviewer does not require direct readability of stored files. Canonical Markdown consequently adds structural parsing complexity, especially for arbitrary Markdown comment bodies, without serving an established access requirement.

Bookmarks also need repository-local storage, but their draft representation used a differently shaped global JSON envelope. RFC-0001 resolved the resulting format and schema inconsistency.

## Decision

Store canonical reviews and bookmarks as private repository-local JSON artifacts:

- `.reviews/<review-id>.json` uses schema `fiew.review/v1`;
- `.bookmarks/bookmarks.json` uses schema `fiew.bookmark/v1`;
- both use `{ "schema": "fiew.<artifact>/v<version>", "data": ... }` with no separate version field;
- both retain atomic replacement, a same-directory validated `.bak`, recovery, and future-schema refusal.

Canonical files are internal implementation details. `fiew review show --format json|markdown` emits public projections that preserve complete public review semantics but may omit persistence, repository-identity, allocation, recovery, and re-anchoring metadata. Agents continue to read and reply only through commands; canonical JSON does not grant direct mutation authority.

Reject legacy Markdown reviews rather than migrating them. Do not migrate unreleased global bookmark data. fiew neither checks nor modifies Git ignore configuration.

This decision supersedes only ARP-0007's choice of Markdown as the canonical review format and its `.md` filename consequences. ARP-0007's thread model, reviewer authority, approval rules, and command-mediated agent interface remain accepted.

## Rationale

A unified typed JSON envelope gives reviews and bookmarks one strict parsing and evolution discipline. JSON strings naturally preserve arbitrary Markdown comment bodies without structural delimiters. Separating private storage from public command projections permits internal metadata to evolve without accidentally expanding the agent contract.

Keeping one JSON file per review preserves independent review identity and atomicity; one bookmark collection per repository avoids redundant repository identity filenames. A JSON/Markdown hybrid was rejected because it would introduce multi-file identity and recovery complexity without a readability requirement.

## Consequences

- Existing `.reviews/*.md` files are unsupported legacy artifacts and are rejected clearly.
- New review IDs resolve to `.json`; `.md` is no longer an accepted canonical extension.
- Review JSON output is a stable public DTO, not a byte-for-byte or lossless rendering of canonical storage.
- Bookmark data becomes visible to repository-local tools at `.bookmarks/`, though it remains absent from review command output.
- Users manage ignore rules themselves; fiew may create these directories regardless of Git ignore state.
- ARP-0007 and the v0.1 specification require targeted updates to remove canonical-Markdown requirements while retaining the reviewer-agent authority model.
