# Integrate Tree-sitter behind a direct C adapter

## Context

fiew v0.1 needs responsive Zig and Markdown syntax highlighting, folding, and structural navigation. It is built with Zig 0.16.0, has no source-editing behavior, and must preserve full viewing and navigation when parsing is unavailable or slow. The compatibility evidence is recorded in [Tree-sitter integration constraints for fiew v0.1](<docs/research/tree-sitter-integration-constraints-for-fiew-v0-1.md>), and the accepted product boundary comes from [Decide parsing, highlighting, and folding architecture](<.project/issues/ISSUE-0008-decide-parsing-highlighting-and-folding-architecture.md>).

## Decision

Statically compile Tree-sitter v0.26.13 at commit `d97971e24500218865c05ed1febdee2acf41bae1` and call its C API through a thin Zig adapter. Pin Zig grammar revision `6479aa13f32f701c383083d8b28360ebd682fb7d` and Markdown grammar revision `a0a00f817d02412bd92c54d316f164d827b57b5c` with package integrity hashes.

The adapter owns all C lifetimes and exposes only immutable fiew-owned parse snapshots, normalized highlight spans, fold ranges, and structural navigation results. Parsing runs in cancellable worker jobs and never in the render loop. Highlight queries run for the viewport plus overscan outside cell rendering. Plain text remains the complete fallback.

Support Zig and Markdown only. Markdown uses its block and inline parsers and allows one level of Zig injection for explicitly labeled `zig` fences. Use Tree-sitter fold queries only: the grammar's Zig query and fiew-owned Markdown section/fence queries. Do not use indentation folding.

## Rationale

Tree-sitter's stable C API provides the required input, cancellation, included-range, ABI-checking, and range-limited query capabilities. Direct integration avoids another wrapper dependency and gives fiew one ownership boundary. Worker snapshots decouple terminal responsiveness from parser latency. Restricting grammars and injection depth keeps the first integration testable, while plain-text fallback preserves the core read-first workflows under every parser failure.

## Consequences

- The implementation must verify grammar ABI compatibility and contain C allocation and destruction in the adapter.
- Files over 2 MiB remain plain text. Jobs show pending status after 100 ms and cancel after one second; these policies require later profiling.
- Parsing or query failure disables highlighting, folding, and structural navigation without blocking text navigation.
- Markdown syntax output is presentation assistance, not correctness-critical interpretation.
- Dependency upgrades require explicit ABI, query, ownership, and performance verification.
- Additional languages, nested injections beyond one level, indentation folding, and semantic navigation are deferred.
