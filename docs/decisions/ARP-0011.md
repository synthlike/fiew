# Store Trails as review-keyed private companion records

## Context

fiew v0.2 adds reviewer-curated Trails: ordered source locations that belong to an active named review. Trails need durable review-local identity and conservative anchor metadata, but they are not review threads or comments. The established `fiew.review/v1` schema and command-mediated agent projection form an authority boundary that Trails must not silently expand.

The accepted behavior is specified by [fiew v0.2](<docs/specs/fiew-v0-2.md>) and motivated by [Trails for review-local reading paths](<docs/product/trails-for-review-local-reading-paths.md>).

## Decision

Persist saved Trails as private schema-versioned `fiew.trail/v1` companion records keyed to the active review identity under the existing repository-local `.reviews/` write boundary.

Keep canonical Trail data separate from `fiew.review/v1` and `fiew.bookmark/v1`. Do not include Trails in `fiew review show`, agent reply input, approval state, or other agent review projections. Use the existing atomic replacement, validated backup, recovery, and future-schema refusal discipline.

In-progress recording and metadata composition remain memory-only. A future explicit reviewer action may project a Trail into ordinary comment text, but canonical Trail records never become implicit agent-visible review state.

## Rationale

Embedding Trails in `fiew.review/v1` would couple an explanatory navigation artifact to thread lifecycle, change an established schema, and risk expanding agent-visible semantics. Repository-global Trail storage would lose the active-review ownership accepted for the workflow. Bookmark storage would erase ordering, Trail metadata, and review identity.

A separate companion schema preserves review and bookmark compatibility while retaining review-local lifecycle and the existing narrow `.reviews/` write boundary. Explicit future text projection keeps publication under reviewer control.

## Consequences

- Trail storage requires a dedicated model and adapter but reuses existing JSON envelope and recovery conventions.
- Deleting or failing to load Trail data cannot alter review approval, threads, comments, or bookmarks.
- Review deletion and orphaned companion cleanup need an explicit implementation policy; they must not be inferred by changing review schema.
- Agents cannot discover Trails through current review commands.
- Printing a Trail into a comment remains a separate future product and authority decision.
