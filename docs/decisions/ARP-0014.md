# Store containers, Trails, and Spots as independent repository artifacts

## Context

fiew v0.3 adds durable Discoveries, structured links between Discovery Threads and Review Concerns, and agent-proposed Trails attached atomically to replies. The v0.2 Trail decision stores one review-keyed collection beside its Review under `.reviews/`. That physical ownership cannot represent Discovery-owned or repository-private Trails cleanly and gives an independently referenced Trail no stable artifact identity.

No production Review, Bookmark, or Trail records exist. Clean persistence contracts and explicit purge are preferable to speculative migration machinery. The complete accepted boundary is recorded by [Choose Discovery and generalized Trail persistence compatibility](<.project/issues/ISSUE-0077-choose-discovery-and-generalized-trail-persistence-compatibility.md>).

## Decision

Persist each durable container and independently referenced artifact in its domain-owned repository directory:

- one `fiew.discovery/v1` file per Discovery under `.discoveries/`, with an independent validated current pointer;
- one `fiew.review/v2` file per Review under `.reviews/`, with the existing independent current pointer;
- one redesigned pre-release `fiew.trail/v1` file per Trail under `.trails/`;
- one bounded `fiew.spot/v1` collection under `.spots/`.

Every Trail has one immutable Review, Discovery, or repository-private owner. Ownership does not imply agent visibility. A container exposes a Trail only through an explicit attachment reference stored in that container. Human Trails default private; an agent-proposed Trail is attached to its originating Comment.

Use opaque repository-local IDs for artifact and relationship identity. Filenames remain adapter-controlled storage details. Preserve private JSON, bounded validation, atomic single-file replacement, one validated backup, and future-schema refusal.

Use narrow owner-local transaction journals under `.discoveries/.transactions/` and `.reviews/.transactions/` when one operation changes a pointer or standalone Trail alongside its container. Recover or roll back an interrupted intent before exposing either side. An unrecoverable intent disables only the affected container's mutation and agent projection.

Before v0.2 release, replace review-keyed `.reviews/*.trails` collections with one-file-per-Trail `.trails/` storage. No legacy Trail data exists, so ignore development companions without migration or diagnostics. v0.3 may require manual purge of incompatible development Review and Bookmark records rather than reinterpret or overwrite them.

## Rationale

Independent Trail files provide stable structured references, isolate corruption and updates, and support Review, Discovery, and private ownership without coupling physical storage to one container type. Keeping attachment references in containers separates ownership from deliberate agent visibility.

One file per Discovery or Review preserves atomic conversation ownership. Spots remain one collection because they are private, small, and not independently attached. Owner-local journals add crash consistency only where filesystem replacement cannot atomically update multiple fiew-owned files; they do not create a general database or event log.

A clean schema boundary avoids migration and dual-format complexity while there are no production records. Explicit refusal and purge remain safer than guessing at old semantics.

## Consequences

- [Store Trails as review-keyed private companion records](<docs/decisions/ARP-0011.md>) is superseded.
- The v0.2 specification and implementation must move Trails to `.trails/` before integrated verification and release.
- v0.3 specifications must define `fiew.discovery/v1`, `fiew.review/v2`, and `fiew.spot/v1` observable contracts and purge requirements.
- Review and Discovery adapters must coordinate bounded expected-revision transactions for pointer and attachment operations.
- A malformed standalone Trail cannot disable unrelated Trails or source browsing.
- fiew gains `.discoveries/`, `.trails/`, and `.spots/` as private repository-local write boundaries while retaining `.reviews/`; it never changes Git ignore configuration.
