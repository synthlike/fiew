# Keep Discovery and Review distinct while sharing anchored artifacts

## Context

fiew's review threads provide durable human-agent conversations, but their diff anchors, resolution lifecycle, and approval consequences make them unsuitable for ordinary questions about existing code. Trails are also useful beyond review because a human or agent can use an ordered, annotated path to explain a code flow.

[Add durable Discoveries and explanatory Trails alongside Reviews](<docs/rfcs/RFC-0004.md>) resolved whether to generalize Review, add standalone repository threads, or introduce a separate knowledge-oriented container.

## Decision

Keep two distinct durable repository containers:

- **Discovery** supports code understanding through human-created source-anchored threads with human-controlled Open, Answered, and Archived lifecycle.
- **Review** evaluates changes through review concerns whose Current or Outdated state and Open or Resolved lifecycle retain their established approval consequences.

Share explicit concepts where their semantics agree: append-only human-agent comments, immutable provenance, conservative repository-relative anchors, independent Current or Outdated anchor validity, command-mediated agent access, and explanatory Trails.

A repository may have one human-selected current Discovery and one human-selected current Review simultaneously. Agent operations never change either pointer. Discovery threads never become review concerns implicitly; a human may create a linked concern while preserving separate lifecycles.

Treat Trails as ordered explanatory navigation artifacts that may attach to a Discovery or Review without affecting approval. An agent may propose a Trail only while replying to an existing human-created thread. The proposal belongs to the same container, is referenced as a structured reply attachment, and requires human acceptance. Agent authorship remains immutable after acceptance.

Automatically re-evaluate anchors through constrained exact context, but never archive a thread because of age or anchor loss. Archival remains human-controlled and retained artifacts remain restorable and referenceable.

## Rationale

One generic container would conflate knowledge completion with review resolution and source anchors with diff anchors. Standalone repository threads would either expose unrelated history during agent handoff or require routine identifier exchange. Named Discoveries provide bounded durable context while Reviews preserve a clear approval boundary.

Shared artifact concepts keep navigation, anchoring, provenance, and agent interaction consistent without hiding meaningful lifecycle differences. Proposed Trails let agents explain code flows structurally while preserving human control over durable accepted knowledge.

## Consequences

- Discovery becomes the canonical product term; Investigation is not used for this container.
- Discovery and Review require independent identities, current pointers, projections, lifecycle rules, and command namespaces.
- A future specification must define Discovery interaction, storage, compatibility, agent commands, structured Trail attachments, and links to review concerns.
- Existing `fiew.review/v1` and `fiew.trail/v1` behavior remains unchanged until explicitly superseded.
- [Store Trails as review-keyed private companion records](<docs/decisions/ARP-0011.md>) remains authoritative for v0.2; a future Trail ownership decision may supersede its review-local boundary.
- External-file Discovery anchors, fuzzy relocation, automatic archival, and unsolicited agent-created threads or Trails remain excluded.
