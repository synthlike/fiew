# Adopt Skaut as the complete product identity

## Context

The project reached a pre-v0.2 point where its original `fiew` name no longer matched the established Discovery, Review, Spot, and Trail product language. The rename decision is recorded by [Rename fiew to Skaut before v0.2](<.project/issues/ISSUE-0084-rename-fiew-to-skaut-before-v0-2.md>).

The unscoped npm package `skaut` is already owned by an unrelated web-crawling project. The project does not require unscoped npm distribution. Existing fiew v0.1 release bytes and workflow records form truthful history, while no production persistence compatibility obligation exists for v0.2 development state.

## Decision

Adopt **Skaut** as the complete current product identity before v0.2:

- product and UI name: **Skaut**;
- executable, repository, Zig package, installation paths, and global-state directory: `skaut`;
- environment-variable prefix: `SKAUT_`;
- private schema prefix: `skaut.`;
- public Agent Skill: `skaut` from `synthlike/skaut`;
- any future npm launcher: a scoped package such as `@synthlike/skaut`, never the occupied unscoped name.

Retain the established Discovery, Review, Concern, Spot, Trail, Thread, Comment, and Anchor vocabulary. Retain generic repository-local directories such as `.reviews/`, `.bookmarks/`, `.trails/`, `.discoveries/`, and `.spots/`.

Make a clean identity break. Do not add aliases, migration, fallback paths, old-name detection, or special diagnostics for fiew schemas, commands, paths, or state. New Skaut builds naturally ignore old global paths and treat non-Skaut schemas through ordinary invalid-schema behavior.

Preserve opaque workflow-managed record paths and factual historical mentions. Rename the GitHub repository while retaining redirects. Preserve the v0.1.0 tag, release title, binary, and assets as the historical fiew release; v0.2.0 is the first Skaut release.

## Rationale

A complete rename avoids permanent split identity across UI, CLI, storage, distribution, and agent interfaces. A pre-release clean break is simpler and safer than migration code for development data. Stable historical references preserve auditability, and retaining the real v0.1 artifacts avoids relabeling bytes that still identify themselves as fiew.

## Consequences

- Existing development state may require manual deletion; Skaut provides no migration or purge command.
- Current specifications, active plans, tests, skills, packaging, and release guidance must use Skaut identities.
- Historical fiew records and release artifacts remain discoverable and accurate.
- The repository transition and complete distribution verification must finish before integrated v0.2 verification and release.
- Future distribution work cannot assume ownership of the unscoped npm package name.
