# Structure fiew as a single-owner event-driven application

## Context

The v0.1 workflows combine deterministic modal interaction with terminal I/O, document loading, parsing, Git subprocesses, filesystem refresh, ZLS JSON-RPC, Mermaid rendering, and persistent review state. Slow or stale integration results must not mutate current UI state, and third-party types must not determine product architecture. The accepted scope is consolidated in [Choose the v0.1 internal architecture and dependency strategy](<.project/issues/ISSUE-0012-choose-the-v0-1-internal-architecture-and-dependency-strategy.md>) and builds on [Adopt libvaxis’s low-level API for fiew v0.1](<docs/decisions/ARP-0001.md>), [Integrate Tree-sitter behind a direct C adapter](<docs/decisions/ARP-0002.md>), [Use trusted ZLS as an optional definition provider](<docs/decisions/ARP-0003.md>), and [Render a Mermaid subset as terminal text](<docs/decisions/ARP-0004.md>).

## Decision

Use a single-process event-driven architecture. One UI thread owns mutable `AppState`, command dispatch, focus, selections, views, and application of completed events. A typed command registry performs synchronous state transitions and emits typed effects. Background work returns immutable events carrying owner, operation, source generation, deadline, and cancellation identity; only the UI thread may accept them, and it rejects stale results.

Apply ports-and-adapters dependency direction. The core contains only fiew-owned model, application, port, view-model, and render-plan types. Adapters translate libvaxis, Tree-sitter, Git, filesystem, JSON-RPC, Mermaid subprocess, and state-storage data. Third-party types never enter core state. Rendering is pure from application snapshot and terminal dimensions to a ViewModel and then a cell RenderPlan; the terminal adapter only applies that plan.

Represent all text with immutable, versioned `DocumentSnapshot` values containing origin, bytes, line/display mappings, generation, encoding status, and captured file metadata. Selections, history, folds, parse results, diffs, and LSP requests use snapshot identity and byte ranges. NUL-containing files are binary metadata views. Invalid UTF-8 renders replacement characters through preserved byte mappings and disables parser/LSP/Mermaid features without changing source bytes.

Use a bounded general worker pool for loading, parsing, Git, and Mermaid effects; dedicated per-repository ZLS supervisors for ordered JSON-RPC lifecycle; and coalescing filesystem notifications. Use the installed Git CLI through a read-only adapter with explicit machine-readable options and snapshot consistency checks. Persist global state and per-repository notes as schema-versioned JSON through one state-store adapter using atomic replacement and one validated backup.

Organize source under `model/`, `app/`, `view/`, `ports/`, and adapter-specific directories, with `main.zig` as the composition root. Keep imports acyclic and split further only for demonstrated behavior.

## Rationale

A single state owner makes modal transitions, preview behavior, and stale-result rejection testable without locks throughout the model. Typed effects isolate latency and process lifecycles. Ports-and-adapters boundaries prevent integration libraries and wire formats from coupling interaction behavior. Immutable snapshots give parsing, diffs, LSP, history, and reloads one consistent identity model. Pure rendering and fixture-driven adapters support deterministic verification without Ghostty, network access, or optional executables.

The Git CLI preserves Git's own behavior without adding libgit2. Versioned JSON is sufficient for the small local state boundary and avoids a database and migration system before evidence requires them.

## Consequences

- Linked dependencies remain libvaxis, Tree-sitter core, and the Zig/Markdown grammars at accepted immutable revisions and integrity hashes.
- Runtime tools are Git for Git workflows, optional ZLS 0.16.x, and optional `mermaid-ascii` 1.5.x. No libgit2, SQLite, generic LSP library, widget/application framework, Node, or Chromium is admitted without a later decision.
- The implementation must provide bounded queues, cancellation, coalescing, generation validation, orderly process shutdown, and terminal restoration.
- Persistent files require schema validation, atomic writes, future-version refusal, and bounded backup recovery. They must not contain source, blobs, protocol payloads, note text in logs, environment values, or secrets outside the explicit note store.
- Tests follow boundaries: pure unit/reducer tests, render-plan snapshots, fixture/transcript adapter contracts, ownership/leak tests, fuzz/property checks, opt-in tool integrations, and manual Ghostty protocol checks. `zig build test` remains deterministic without network or optional tools.
- Adapter failures become typed events, disable only their capability, preserve the last valid snapshot, and feed bounded redacted diagnostics. Fatal terminal failures restore the terminal before reporting.

## Partial supersession

[Keep Mermaid rendering outside fiew](<docs/decisions/ARP-0012.md>) supersedes the Mermaid-specific clauses in this decision. The single-owner event-driven, immutable-snapshot, ports-and-adapters, and bounded-effect architecture remains accepted; Mermaid adapters, effects, runtime tools, and feature-specific fallback are no longer planned.
