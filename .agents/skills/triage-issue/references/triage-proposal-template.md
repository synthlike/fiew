# Triage proposal

## Incoming report

Summarize the observation or request without adding causal interpretation. Link the original source when one exists.

## Classification

State the closest project classification and rationale. Keep reported impact, verified evidence, urgency, and severity distinct.

## Existing and authoritative context

- **Duplicates or overlapping issues:** Links and exact outcome overlap.
- **Prior disposition:** Relevant resolved, cancelled, or rejected work and rationale.
- **Authority:** Specifications, accepted ARPs, domain documentation, or current behavior that establish expectations.

## Evidence and missing information

List verified evidence, unverified claims, reproduction needs, external facts, human intent, and design decisions still required.

## Recommended disposition

Choose one: duplicate or covered, answered question, request evidence, route to another workflow, create an issue, or update an issue. Explain why this is the smallest useful next step.

## Proposed issue

Include only when executable work is ready for approval.

- **Title:** Bounded outcome
- **What to build:** Observable end-to-end behavior
- **Acceptance criteria:** Verifiable outcomes
- **Links:** Authority and supporting evidence
- **Blockers:** Only prerequisites that genuinely prevent starting

## Proposed backend operations

List every create or update operation that would occur after approval. Do not perform it from this draft.
